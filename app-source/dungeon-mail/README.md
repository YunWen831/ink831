## 游玩

- WASD / 方向键移动；手机使用左下摇杆。
- 靠近跑酷工坊、地牢邮局或画室时按 E（手机点互动按钮）。工坊与邮局打开对应的房间列表。
- Enter 聚焦聊天，输入时不移动角色；Escape 回到地图。聊天栏可切换“局外·大厅”和“局内·小队”：大厅频道广播所有在线玩家，小队频道严格限制本房间成员，各自保存历史，最多保留各自最近 50 条消息，单条 120 字。聊天保留 30 分钟，服务器每分钟清理并通知在线页面删除过期消息；发给新加入者的历史立即过滤过期内容。聊天不写入存档。
- 气泡按字数显示约 5～15 秒，自动换行，优先显示自己和最新消息并避开人物；同时最多绘制 8 个气泡，拥挤时其余消息仍可在聊天栏完整阅读。
- 跑酷练习使用 A/D 或方向键左右移动，Z 跳跃，方向键配合 X 八方向冲刺；落地或碰到晶石补充冲刺，R 从当前检查点重试。手机使用摇杆及“跳”“冲”按钮。选择段落可直接试蹬墙、冲刺或连跳；“重来”从头开始。聊天输入框、弹窗、后台或断线时暂停练习。
- “画方块”提供彩虹色相条、饱和度/明度二维渐变、R/G/B 渐变滑条和数值输入，任意 RGB 与 HEX 双向同步；32 个经典鲜艳色和 64 个柔和建筑色可切换，并保留吸色、橡皮、填色和撤销。画板可选 16×16、32×32、64×64，默认新画作 32×32；切换按最近邻缩放现有画面，撤销可恢复原分辨率和细节。草稿保留在当前浏览器；保存的材料进入共享材料栏。
- 地图为 4096×3072，共 128×96 格，含原道路和地图边缘在内的所有地块均可建筑；点击或拖动在角色附近 160 世界像素内施工。墙块挡路，地砖可走。玩家所占位置不能新建墙块。
- “回广场”在出生点被占时寻找空地，不删除已有建筑。建筑按固定账号 ID 记录放置者，默认禁止他人拆除或覆盖；“我的账号”中可以开放权限，不划定私人土地。旧建筑保留，归属由站长独立确认。缩略地图可查看当前位置。
- 人物支持四方向朝向、交替迈步和摆臂；开启系统“减少动态效果”后关闭步行动画。

## 跑酷机关

编辑器保留方块、尖刺与晶石，新增机关统一放在“机关”菜单。八类机关：尖刺、晶石、弹簧、单向平台、移动平台、坍塌平台、开关与机关门、风场。

- 弹簧从上方着地触发，自动弹起并补充冲刺；单向平台可从下方穿过，↓ + Z 穿下（手机摇杆向下 + 跳）。
- 移动平台可横向或纵向往返（4 秒周期、通常单边 48px）；可从下方穿过，上方落稳后随行。边界附近缩短轨道，保留出生区与接缝安全。
- 坍塌平台踩踏后 0.4 秒消失，触发 3 秒后恢复；开关触碰后开启本张地图所有门 4 秒，离开后可再次触碰。关闭或恢复时若卡进角色，快速重生。
- 风场有四个方向，可连续画成区域；相邻风格不叠加强度，冲刺期间不改变速度。
- 机关、补充物与计时对每位跑者独立，重试和进入下一张地图时重置机关时钟与门、坍塌状态。未结束的玩家接收自己的状态；终点观战额外接收被观战者的机关与晶石状态。
- 每张图最多 32 晶石、64 弹簧、横纵合计 12 移动平台、48 坍塌平台、12 开关、48 门、每方向 64 风格。单向平台遵循地图单元数上限。复制粘贴与服务端使用同一规范化限制。

“练习”中可在身法练习与机关练习之间切换，再选具体段落。旧 0–3 地图原样保留；物理规则版本提升为 `parkour-2`，旧云端验证证明失效，需要亲自重跑后保存。不会清空关卡、账号或大厅作品。

## 跑酷对局

房间中 2～4 人在线并准备，由房主进入编辑阶段。每人一张 48×24 格地图，每格 24 像素：方块、尖刺、最多 32 个补充晶石和擦除；两端保留安全通道，避免地图拼接时堵住出入口。支持拖动绘制、平移和缩放，手机也可通过工具与横向滑条操作。编辑时彼此不展示完整地图，只共享验证进度。

点击“试跑验证”，服务器运行与练习相同的物理并判定是否抵达终点；编辑后旧验证立即失效。所有人验证完成并在线后，房主点“开始竞速”。赛道按进入编辑时的成员顺序拼接，3 秒倒计时后共同出发，彼此不碰撞；每段入口自动成为检查点。成绩与抵达顺序由服务器计时，10 分钟结束未完成的一轮。结束后可“再跑一轮”，或由房主选择“编辑下一轮”保留源地图重新编辑；编辑阶段仍可返回准备。比赛中退出不会打断其他玩家。

造图草稿按账号 ID（游客按昵称）自动保存在当前浏览器 localStorage，同一编辑房间内也保留在服务器内存，刷新与 60 秒内重连可恢复。本机草稿与账号关卡库分开，跨设备需要点击“保存到账号”；服务器重启会结束当前对局，但不会删除浏览器草稿、材料和大厅建筑。

服务端按实际经过时间推进 120Hz 固定步长物理，不因输入包数量而加速。输入逐帧序号、房间身份、每轮 ID 和队列上限校验；没有客户端直接提交成绩的接口。本机预测并重放尚未确认的输入，其他玩家平滑显示，状态每 50ms 同步；玩家元数据只随进入对局下发，位置使用紧凑数组，晶石只传活跃冷却。聊天或后台期间多人对局仍继续，单人练习可以暂停。

跑酷角色采用原创像素绘制，独立于 16×24 碰撞体，包含交替跑步、起跳收腿、下落、贴墙及冲刺姿态；围巾颜色表示冲刺是否可用。没有改变跳跃、冲刺和移动参数。

默认大厅和准备房间共用一个 Colyseus 连接，玩家以逻辑空间隔离，避免切换空间时重新握手。整个服务最多 50 个连接（包含准备房间和短暂断线保留的位置），准备房间最多 4 人、同时最多 12 间。默认大厅不会因最后一人离开而销毁，也不会在满员时另开一个大厅。


## 账号、作品与人物

账号是 3～24 位字母、数字或下划线（不区分大小写）；昵称独立可改，允许重名。永久归属只认服务器分配的 UUID。密码为 12～128 字符，界面显示“请勿使用常用密码防止泄露”。服务器采用随机独立盐的 scrypt（N=2^17、r=8、p=1），同时最多运行两次哈希；无明文密码或可逆密码存储。

会话有效期三十天，每账号最多五个；随机会话令牌只通过 `__Host-` Secure、HttpOnly、SameSite=Strict Cookie 传递，磁盘只保存令牌哈希。退出撤销当前会话；改密/找回撤销全部旧会话，并更换找回码。账号接口限制请求来源、请求大小、IP 与账号尝试次数。WebSocket 加入、重连及消息处理都会核对服务器会话；退出后最多一秒断开旧连接。注册/找回时找回码只显示一次，丢失密码和找回码后需要联系站长，暂不提供短信或邮件。

`accounts.json`、`world.json` 与 `avatars/ACCOUNT_ID.json` 均在外部 DATA_DIR，以串行原子替换写入，权限 0600。账号不需要额外付费服务。账号存档、密码哈希和会话哈希都不能通过前端内容接口导出；用于标记作品归属的用户 ID 可以公开。游戏页与 API 同源，减少第三方 Cookie 限制造成的登录失败。

游客可移动、聊天、单人练习和参加跑酷；持久绘画、人物保存、放置和拆除只允许已登录账号。

大厅人物改为部件绘制：头、身体、左右手臂、左右腿，正面/背面/侧面各一套，另一侧自动镜像。提供完整模板，玩家可改其中任意部件；支持同尺寸复制粘贴、镜像到另一侧、橡皮、填色、吸色、撤销和本机草稿恢复。编辑器直接预览自动步态，不再要求画站立/迈步每一帧。

`avatar-rig.js` 定义有界部件数据，`avatar-motion.js` 根据距离相位驱动摆臂、两段腿和脚掌落点，正背面用纵深抬脚、侧面弯膝，脚底保持平直；停止时缓和回站姿。`avatar-render.js` 缓存部件和姿态，不为每一帧上传图片或增加移动同步字段。新部件贴图约 33KB 十六进制文本（原逐帧约147KB），仍按3072字符分块、20秒截止、WebSocket单消息4096字节限制，完整校验后才保存和广播。

已有逐帧自绘人物继续按旧方式显示。打开绘制时可预览拆分后的部件，明确保存后才替换；不适合拆分的形状显示模板并提示替换影响。本机旧稿同样可转换，左右不对称作品需检查镜像侧面。人物碰撞、速度和跑酷物理未改，跑酷仍使用其现有角色。

## 管理员

使用管理员账号登录后，在“我的账号 → 管理账号”进入。支持搜索账号、修改昵称、封禁/解封、强制下线、重置登录、修改指定账号的建筑拆除/覆盖设置，以及查看、预览、删除/恢复其他玩家自绘方块。作品删除沿用12小时回收站与建筑贴图归档。大厅工具栏新增管理员专用“批量拆除”：桌面拖框或手机依次点两个角，服务器预览范围和数量后确认，可拆除所有归属和保护状态的墙块、地砖、导入图，包括未绑定旧建筑；保留材料画布。预览绑定管理员当前登录会话，2分钟有效，提交时在存档队列内再次核实管理员权限及选区内容摘要。选区被编辑后整批拒绝，需重新预览，避免误拆新建筑。一次原子存档并同步所有玩家碰撞与地图，记录管理日志。普通账号无入口，直接调用接口也被拒绝。

敏感操作先显示目标与影响，保留最近200条管理记录，页面展示最近50条。

管理员身份由外部 `DATA_DIR/admins.json` 的 `{version:1,ids:[ACCOUNT_UUID]}` 绑定真实账号ID；文件0600，部署时已为现有 `ink` 账号配置。注册同名昵称、修改客户端或提交admin字段均不能取得权限。服务器对每次HTTP请求及排队中的世界修改重新检查会话和权限；普通账号不能读取管理列表。管理员账号禁止从管理面板封禁或重置自身。

封禁与强制下线撤销全部登录；被撤销的连接立即释放位置，正常掉线仍有60秒重连。重置登录停用旧密码并生成仅显示一次的新找回码，由管理员私下交给本人在“找回密码”设置新密码，密码本身不显示、不写入日志。封禁期间找回码也不能恢复登录。

材料库的“我的画布”只显示本人作品及删除按钮，服务器再次校验作者 ID。删除进入12小时回收站，12小时内可恢复；已建建筑始终保留纹理，删除的材料不能继续新放置。启动时和每30秒自动清理到期材料；到期即拒绝恢复。没有建筑引用时删除贴图；仍被引用时仅保留地图渲染归档，不能恢复、新建或出现在材料库与管理员画布列表中。导入图贴图单独标记并隐藏，不占普通材料128项名额，废弃且无引用的导入贴图也自动清理。共享材料的绘制者与方块放置者分别记录，使用别人的材料不转移建筑所有权。

旧版作品与方块没有可靠账号 ID，因此保留但禁止同名自动认领。管理员可直接使用大厅拆除/放置工具拆除或覆盖旧建筑，并在“管理账号 → 旧画布”中删除/恢复未绑定旧画作；普通账号仍不能操作这些旧内容。旧建筑操作保存管理记录，排队写入时再次校验管理员会话。站长确认后可停服并备份 DATA_DIR，使用 `DATA_DIR=... node assign-legacy.js ACCOUNT material MATERIAL_ID` 或 `... ACCOUNT tile COL,ROW` 分配未归属内容；操作完成后重启。该工具只供服务器管理员离线运行，不对玩家开放，也不能覆盖已有归属。

每日备份现在同时保存兼容的 world 日期快照与 `state-YYYY-MM-DD.tar.gz`，后者包含 world、accounts、avatars、levels、admins，保留十四个日期。恢复账号版时必须恢复相匹配的完整 state；不要只回退 world 而丢弃账号或人物。上线前另保留完整源码与 data 的部署备份。

后续顺序见 [ROADMAP.md](ROADMAP.md)：跑酷完善 → 像素伪装捉迷藏 →《把地牢寄给你》。

## 账号关卡库与编辑体验（0.7）

在“房间 → 跑酷 → 我的关卡”进入账号关卡库；不必等待队友，可独自新建、编辑、验证和保存。每账号最多保存 24 张，支持命名、载入、存为副本及本人删除。多人房间编辑阶段也能载入自己的账号关卡。关卡库当前仅本人可见，尚未开放公共分享或长期排行榜。

“保存到账号”会先等待本机改动与服务器同步，再保存明确的地图版本。地图在另一设备更新后，旧设备覆盖会收到冲突提示，可载入新版或“存为副本”，不会静默覆盖。账号文件位于 DATA_DIR/levels/UUID.json，串行原子写入、0600；同账号多个会话共享关卡库，不同账号不能读取或修改彼此记录。

服务器实际通关后才生成验证证明，绑定准确地图内容和 MAP_RULESET。已存入账号的地图验证通过会自动更新证明；未存档的新图可在验证后手动保存。以后载入本人同一已验证布局可直接使用，改动几何后撤销验证；只改名称保留证明。客户端提交的 verified/proof 无效。后续更改物理或地图语义时必须提升 level-store.js 中 MAP_RULESET，使旧证明过期。

编辑器支持以整次拖动为单位的撤销/重做（60 步）、框选、复制、粘贴与清除选区；Ctrl/⌘+Z 撤销，Shift+Ctrl/⌘+Z 或 Ctrl+Y 重做，Ctrl/⌘+C/V 复制粘贴，Delete 清除选区。粘贴需要点击画布确定位置，始终保留两端通道与 32 晶石限制。新载入地图分配独立 documentId，旧编辑器迟到的更新不能覆盖新文档。

本机草稿仍按账号保留，关卡库有“恢复本机草稿”入口；恢复来自浏览器的数据必须重新验证。覆盖当前有未保存改动的地图或离开编辑时，会先提醒。云端保存是明确按钮操作，不宣称每笔画都自动跨设备同步。

成员试跑时共享大致进度（每500ms），不提前公开地图。先抵达终点者可选择观战未完成的队友，镜头跟随目标；重连后仍能继续观战。结算后可直接再跑，也可保留各自原图进入下一轮编辑；未修改的验证仍有效。固定步长物理与 Z/X 操作不变。

每日完整 state 备份包含 levels 文件，恢复时与 accounts、world、avatars 一并恢复。读取账号快照安排在内容文件之后，以包含备份期间刚创建且已保存内容的新账号。

## 本地运行

在本目录执行：

```sh
npm ci --ignore-scripts
npm test
npm start
```

后端默认监听 `127.0.0.1:2567`，同时提供 `/courtyard/` 页面及同源 config。仅在本机 HTTP 开发时设置 `COOKIE_SECURE=0`，打开 `http://127.0.0.1:2567/courtyard/` 即可，无需更改正式 endpoint。生产环境必须保持 Secure Cookie 和 HTTPS；隔离浏览器验收通过只绑定回环地址的 SSH 转发访问候选服务。

`ALLOWED_ORIGINS` 为逗号分隔的允许网页来源，默认包含腾讯云 HTTPS、GitHub Pages 与开发用本地地址。`AUTH_ORIGINS` 单独限定账号 POST 来源；生产环境只允许腾讯云 HTTPS。来源校验覆盖匹配 HTTP 和 WebSocket 握手；每来源 IP 的匹配请求限制为每分钟 120 次（不与账号接口共用额度），以容纳同一校园出口的玩家。来源限制不替代账号认证。

## 存档与部署

当前公网后端部署于腾讯云北京轻量应用服务器，Ubuntu 26.04 LTS、2 核 4GB、6Mbps。GitHub Pages 保留入口，实际游戏页面和账号接口由同一个腾讯云 HTTPS 来源提供，入口为 `https://82.157.83.81`：

- `/home/ubuntu/dungeon-mail/app/`：只同步游戏源码。
- `/home/ubuntu/dungeon-mail/node-v24.22.0-linux-x64/`：已验证的 Node.js 运行时。
- `courtyard.service`：游戏后端，仅监听 `127.0.0.1:2567`。
- `caddy.service`：公网 HTTPS/WSS，配置为 `deploy/Caddyfile`。
- `DATA_DIR=/home/ubuntu/dungeon-mail/data`：独立于源码的持久目录。
- `courtyard-backup.timer`：每日 UTC 04:00 后随机延迟至多 15 分钟保存 gzip 快照，保留最近 14 个日期。
- `/home/ubuntu/dungeon-mail/backups/`：每日快照和迁移备份；机器外另保留一份迁移备份。每日同机快照不等同于异地灾备。

新机器先准备运行时、依赖和真实存档，再安装 service。`ProtectHome=read-only` 下，游戏后端只有 `ReadWritePaths` 指定的数据目录可写；备份任务只可写备份目录。

```sh
sudo install -d -o ubuntu -g ubuntu -m 700 /home/ubuntu/dungeon-mail/data /home/ubuntu/dungeon-mail/backups
# 在 app-source/dungeon-mail 目录执行
sudo install -m 644 deploy/courtyard*.service deploy/courtyard-backup.timer /etc/systemd/system/
sudo install -m 644 deploy/Caddyfile /etc/caddy/Caddyfile
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl daemon-reload
sudo systemctl enable --now courtyard courtyard-backup.timer caddy
# 后续源码更新
sudo systemctl restart courtyard
sudo systemctl reload caddy
```

不要将存档上传到 GitHub，也不要用候选环境的测试数据覆盖线上存档。更新源码只同步 `courtyard/` 和 `app-source/dungeon-mail/`，保留部署根目录中的 data。

`world.json` 保存自绘材料和公共建筑；成功通知在磁盘原子替换完成后发出。`world.json.bak` 保存上一次写入。若存档损坏则拒绝启动。材料库最多 128 件自绘材料，地图共有 12288 个可编辑格，12 件预设材料不占自绘额度。渲染只遍历视野内的格子，地图不会整体缩小以塞进窗口。

旧版 256 字符的索引像素按原调色板解码，颜色不变；新版存为逐像素 RGBA 色值，16/32/64 格分别为 2048/8192/32768 字符；尺寸可从受限长度推断。旧索引格式与三档 RGBA 格式可以共存于版本 1 存档，无需覆盖或迁移玩家作品。16 格材料直接提交；32/64 格使用有序 2048 字符分块、20 秒截止时间和每客户端最多一件在途上传，完整接收并验证后才写入存档。WebSocket 单消息输入上限仍为 4096 字节，半截上传不会生成作品，断线清除临时上传而保留浏览器绘画草稿。0.16 客户端加入时带 `clientVersion:18`，旧页面需要刷新，确保渲染和聊天清理协议一致。

玩家位置、准备房间和聊天历史暂驻内存；服务器重启后重新进入大厅，材料与建筑仍在。掉线 60 秒内或刷新页面会尝试恢复当前身份、位置和空间。浏览器保存昵称、绘画/人物草稿、材料选择和当前标签页的重连令牌；账号会话使用 HttpOnly Cookie，不把密码或会话 Cookie 放进 localStorage，诊断不包含令牌和聊天内容。

后端重启会结束当前内存房间，玩家需要重新进入；材料和建筑不丢失。切换主机时也不会迁移玩家连接、位置、准备房间或内存聊天历史。

## 公网与证书

云防火墙放行 TCP 80 和 TCP 443。80 用于 ACME HTTP 验证和 HTTPS 跳转，443 用于网页的 HTTPS/WSS；不要公开 2567 或 Caddy 管理端口 2019。

Caddy 使用 Let's Encrypt 的 `shortlived` profile 签发受信任的 IP 证书，并自动续期；无需另买证书或域名。IP 证书有效期较短，需保持 Caddy 运行和 TCP 80 可访问。`default_sni` 解决客户端通过 IP 连接不发送 SNI 的情况。Caddy 必须支持 ACME profile 和 IP 证书（本次使用官方稳定仓库 2.11.7）。

反向代理覆盖 `CF-Connecting-IP` 为实际连接来源，复用后端的每 IP 限流；不信任客户端自行提交的这个头。后端只能从本机访问。

部署检查：`curl https://82.157.83.81/health`、`systemctl status courtyard caddy courtyard-backup.timer`。证书私钥、SSH 私钥、真实存档、玩家内容和迁移归档不得上传 GitHub。
